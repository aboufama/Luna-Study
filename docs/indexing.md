# Indexing latency and source coverage

The OpenAI API path uses `server/indexing.mjs`. Every model call still uses the configured OpenAI organizer, which defaults to GPT-6 Luna. New indexing returns only `{ overview, topics: [{ title, summary, sourceIds }] }` after all required source-analysis work finishes. It does not generate questions, answers, or a spoken script on the import critical path. Older complete saved guides containing `questions` and `script` remain accepted for compatibility.

- Up to 32,000 total text characters: one direct request using all original sources, avoiding the extra map/merge round trip.
- Larger collections: split sources at roughly 18,000 characters, preferring line boundaries. Small chunks from the same test are batched up to 22,000 characters and six chunks. Up to five indexing model calls run simultaneously across requests; queued work starts as soon as a slot opens. The final merge depends on all required chunk results, so it follows that parallel work.
- Each full map chunk is sent as an ordered, lossless catalog of original excerpts. Content/identity/offset-bound IDs identify immutable spans of at most 600 characters; the model reads the complete text and selects one existing excerpt per topic, up to six topics. The server resolves IDs back to exact original spans. This replaces fragile quotation copying and self-counting with an enforced maximum of 3,600 selected characters per chunk. Balanced partitions avoid tiny final selections; short chunks retain their full readable text. Whitespace and Unicode are preserved in the complete catalog.
- Every requested chunk must occur exactly once. Missing/duplicate chunks, foreign/stale IDs, extra generated evidence, invalid offsets, or an incomplete provider response fail indexing. No partial guide becomes ready. A selected citation proves authenticity, not semantic completeness.
- Resolved original excerpts are expanded to their original surrounding paragraph when that context is at most 4,000 characters. Exact occurrence offsets preserve repeated text correctly; overlapping excerpts are deduplicated. This preserves example setup that an isolated span can omit. One final request organizes those excerpts using original filenames and source IDs. Generated topic titles are explicitly fallible hints and never become factual source text. Full original materials remain available for retrieval, grading and question preparation.
- Direct and merge requests aim for a concise overview and 3 to 6 short topics where supported. Every topic must cite supplied source IDs; topic-only output still passes structural and source-reference checks.

The quoted excerpts are a bounded selection, so the index is a study overview rather than an exhaustive replacement for original documents. The map prompt asks for distinct ideas, qualifications, notation, and examples throughout each chunk. Structural checks establish that every chunk was analyzed and its excerpts are authentic; they do not prove semantic completeness of the model's selections.

Exact hashes include the test, model, title, source ID/name, chunk boundaries, and unchanged text. An indexing request for an unchanged complete collection reuses its final guide. On the larger-collection path, adding or editing sources reuses the independently verified chunks that still match; changed small collections use a new direct request. Results are cached in memory for 30 minutes, bounded to 256 entries and approximately two million serialized characters. Restarting the server clears this cache. Without a test ID, requests do not share cache entries.

The browser persists extracted sources and the returned guide in IndexedDB: database `keyval-store`, object store `keyval`, key `study-board-v2`. The server's indexing cache is separate from this saved library. Original binary files are not retained in the material records.

After the indexing response is sent, the existing private question bank is scheduled from the topics. Its idle worker later generates questions and reference answers from the original sources; bank readiness never gates index readiness. The bank is also ephemeral server memory, with up to eight entries and a 30-minute idle expiry by default. A server restart clears both the indexing cache and private bank, while the browser's saved materials and guide remain.

Indexing is an overview of the test's sources, not a vector retrieval index or per-document relevance classifier. The OpenAI live tutor now receives selected original passages from a separate session-local retrieval layer; the CLI compatibility path still receives full sources. The private bank selects source documents by topic source IDs and receives their complete text; Library search matches substrings in filenames and extracted text. See [the exact live context and retrieval contract](tutor-context.md).

Concurrent requests for the same test share identical in-flight work. Each caller owns a subscription: disconnecting cancels its subscription, and provider work is aborted only when no caller still needs it. Failed or canceled work cannot populate the final-guide cache. Cross-test sharing is intentionally disabled so provider usage remains attributable to the correct test.

The debug timeline records direct, map, cache, coverage, and merge stages, source IDs, counts, and elapsed times. It never records source text or quotations. The API's final `index.ready` event records whole-request duration. Cache hits create no model usage events; shared work is billed to its test once.

Under ten seconds is a target for common imports, not a guaranteed deadline. Provider latency, document size, map output, queueing, and the final merge determine cold-indexing time. The implementation does not truncate extraction, skip source chunks, or mark a partial result ready to meet the target.

The final topic-catalog benchmark used three original game-theory PDFs, 25,681 already-extracted characters. Three cold requests completed in 4.461, 3.517 and 4.961 seconds (median 4.461); each used one real Luna request and retained all original text. Same-test cache repeats took 0.4–0.6 ms with no provider call. All three final catalogs passed independent source review. This measures server indexing after extraction, not drag-to-ready browser time, and three samples cannot establish production percentiles.

The former 24,000-character threshold sent this modest corpus through two parallel map batches plus a merge. After the citation repair those three runs succeeded in 11.824–12.925 seconds, but paragraph expansion returned 92–93% of the original text to the merge. The measured single-pass experiment therefore justified moving the default threshold to 32,000. Larger inputs still use the bounded parallel citation path. This speed improvement changes dispatch and catalog instructions; it must not be attributed to citation transport alone.

Earlier direct outputs exposed an omitted essential condition and a wrong inline problem-set attribution. The final generic prompt creates descriptions of concepts/activities, without solved results or retyped document references. Exact source attribution remains in structured source IDs. These failures, the two original quote-copy failures, all trial outputs and review limits are preserved in [the indexing comparison](../benchmarks/indexing-topics/comparison.md). Catalogs are still fallible and selective; original sources ground tutoring and grading.

The older [synthetic smoke artifact](../artifacts/indexing-smoke.json) measured complete guides with questions and scripts (6.15 s / 12.45 s). It remains historical evidence and is not pooled with the current corpus measurements.
